## 0. 本版相对 v1 的变化

v2 在保持 v1 已定方向（门禁、Key 哈希、通用上游插件、`generations/assets`）的前提下，吸收参考项目 **YesNAI_Studio_RP（星彩绘图台）** 的「多账号云端中转 + 持久画廊 + 对外网关 + 自动签到」能力，并按本项目决策改造。主要变化：

1. 新增 **账号池（Account Pool）**：多账号、凭据加密、JWT 自动重登、余额刷新、轮询/余额优先选择、账号级冷却。
2. 新增/强化 **对外网关**：`mode = passthrough | restricted`、完整 `policy` 字段集、restricted 参数改写、失败转移分级、请求/尝试留痕、响应头回传。
3. 新增 **D1 原子预占与并发租约**写法（无事务下用 `INSERT...ON CONFLICT...WHERE` 与 `INSERT...SELECT...WHERE COUNT<max`）。
4. 新增 **计量与日志**：`request_logs`、`request_attempts`、`daily_usage`（并入 `usage_counters` 体系）。
5. 明确 **对外网关密钥（Bearer，哈希存储）与面板会话 Cookie 双通道并存**及鉴权矩阵。
6. 数据模型升级到 **V2**（通用化合并蓝本表）。
7. 明确 **上游默认协议为 `nai-compatible`（默认上游 `nai.rinko.ai` 多账号池）**，兼容 `openai-compatible` 与模板适配器。
8. 更新实现顺序，补充安全章节。

> 凡与蓝本冲突处，一律以「本项目已定决策」为准，并在正文标注说明。本文只吸收蓝本的**机制与工程实践**，不照抄其表结构、鉴权模型与前端形态。

## 1. 项目目标

面向个人、自部署在 **Cloudflare Workers** 的 **NovelAI 生图聚合工作台**：
- 打开项目即为**门禁**（所有者密码 / 朋友分享密码），进入后在**工作台生图**、**查看画廊**。
- 可作为**上游聚合网关**：对外接受 API 请求，改写后透传到可配置的上游，返回图片。
- 支持**分发 API Key** 给别人使用。

## 2. 功能需求

1. **工作台生图 + 画廊**：门禁后进入创作台生图，并浏览作品（画廊来源见决策）。
2. **上游可变**：可接入的生图上游能够运行时增删改启停，不写死。**默认上游为 `nai.rinko.ai` 多账号池**。
3. **账号池**：托管多个上游账号，自动重登、刷新余额、按策略选号、失败冷却与转移。
4. **API 透传与改写**：接受外部 API 请求，改写后透传上游，返回图片；支持格式映射、提示词改写、内容策略、请求控制与失败转移。
5. **分发 API Key**：签发受控的 key 供他人调用（仅存哈希，带策略）。
6. **计量与日志**：按 key/账号记录用量、成本、耗时与每次尝试明细。

### 3.1 沿用 v1（本项目已定）

| 网关策略表达 | 策略字段集落在 `api_keys.policy_json`，作为改写规则的一种作用域 | 蓝本独立 `gateway_keys.policy_json`；本项目**合并进 `api_keys`**（Key 已含权限与限额） |

## 4. 目标架构

### 4.1 统一管线（工作台与外部 API 共用）

```
入站适配 → 归一化 CanonicalRequest → 改写管线 → 路由选上游/选账号 → 出站适配 → 透传 → 响应归一化
```

- **入站适配**：`/v1/images/generations`（OpenAI）、`/v1/nai/generate-image` 与 `/ai/generate-image`（NAI）、`GET /generate`（下游简式 query）→ CanonicalRequest。
- **CanonicalRequest**：`model`（逻辑名）/ `action`（txt2img·img2img·inpaint）/ `prompt{positive,negative}` / `params` / `references[]` / `n`。
- **改写管线**：参数映射 → 提示词改写 → 内容策略 → 请求控制（头/鉴权/超时/重试）。
- **路由**：按 key 的模型权限筛选候选上游，按优先级/权重选择；命中 `nai-compatible` 上游时进入**账号池选号**（见 4.2）。
- **出站适配**：内置协议适配器（`nai-compatible` / `openai-compatible`）+ 通用模板适配器（URL/方法/头/body 模板 + 响应字段映射）。
- **响应归一化**：按入站格式还原（OpenAI→b64/url；NAI→zip/base64；`/generate`→图片二进制）。

### 4.2 账号池（Account Pool）

账号池是 **`nai-compatible` 上游的一种资源**（非独立上游类型）；`openai-compatible` 与模板适配器可使用单账号凭据，也可扩展为池。

- **实体**：`accounts`（见 5.2），归属某个 `upstream_id`，默认归属 `nai.rinko.ai` 上游。
- **凭据存储**：`credential_enc` 为 AES-GCM 密文（`enc:v1:<b64(iv)>:<b64(ct)>`，随机 12 字节 IV），密钥由 `CREDENTIAL_ENC_KEY` 派生；**凭据永不出现在 API 响应**，公开视图仅回 `has_jwt / has_password / has_api_token` 布尔。拒绝 `plain:` 前缀明文。
- **JWT 过期自动重登**：上游返回 401 时，用托管密码/凭据重登一次并回写 `credential_enc`，再重建 token 重试一次；仍失败则换号。
- **余额刷新**：定时或按需调用上游余额接口，成功后写回 `gems_last`。
- **账号选择策略**：`round_robin`（持久游标原子自增，见 5.4）或 `balance_first`（余额优先），按上游配置选择；返回序列首个为本次选号，其余为失败转移顺序。
- **账号级冷却**：失败（401/402/429/5xx）时累加 `failure_count` 并写 `cooldown_until`；冷却期内跳过该账号（`account_rate_state`，见 5.2）。

### 4.3 对外网关

- **`mode`**：`passthrough`（字节原样透传，不解析不改写）｜ `restricted`（解析、校验策略、按 `parameter_mode` 改写）。
- **`policy` 字段全集**（存 `api_keys.policy_json`，restricted 生效）：

  | 字段 | 含义 |
  | --- | --- |
  | `allowed_models` | 允许模型白名单（空=不限制；不在白名单→403） |
  | `daily_requests` | 每 key 每日请求上限（原子预占，超限 429） |
  | `daily_gems` | 每 key 每日 Gems 上限（原子预占，超限 429） |
  | `max_concurrency` | 每 key 同时在途上限（并发租约，超限 429） |
  | `parameter_mode` | `fixed` 时启用固定参数合并 |
  | `fixed_parameters` | 强制覆盖的参数对象（合并进 `parameters`） |
  | `limits` | 各参数上下界 `{field:{min,max}}` |
  | `allow_img2img` | 是否允许图生图 |
  | `allow_inpaint` | 是否允许重绘/局部重绘 |
  | `allow_extra_parameters` | `false` 时拒绝未知参数（按已知参数白名单） |

  > 蓝本还读取但未列入白名单的 `models`、`max_n`/`max_n_samples`、`max_width/height/steps/scale` 等，本项目统一通过 `limits` 表达，字段集以前端为准，避免前后端不一致。
- **restricted 参数改写**：`fixed` → 深拷贝 body 后把 `fixed_parameters` 浅合并进 `parameters`；其余 → 保留原始字节（但已完成策略校验）。
- **失败转移分级**：`401 / 402 / 429 / 5xx` → 换下一个候选账号；其余 `4xx`（参数错误）→ **立即透传**，不转移。全部失败 → 502。
- **请求尝试留痕**：每次尝试写 `request_attempts(request_id, account_id, attempt_no, status_code, error)`。
- **响应头**：回传 `X-Account-Id`（实际服务账号）、`X-Gateway-Attempts`（总尝试数）、`X-Gateway-Request-Id`。
  > 蓝本存在 `X-Ynai-Account` / `X-YesNAI-Account` 命名不一致与大小写问题，本项目统一为 `X-Account-Id` / `X-Gateway-Attempts`。

## 5. 数据模型（D1 · V2）

图片对象存 **R2**，元数据与计数存 **D1**。V2 合并本项目 v1 通用表与蓝本账号池/网关表，**字段以本项目通用化为准**。

> **不建**蓝本 `gateway_keys_v7` 中间表与 `active_concurrency` 死列。

### 5.2 持久画廊

- 上传：原图 → R2 `img/{uuid}`，缩略图 → R2 `thumb/{uuid}`（缩略图由前端 canvas 生成后一并上传）；D1 写 `generations` + `assets` 元数据。
- 取图：`GET /api/gallery/i/{id}?t=img|thumb` → R2 读对应对象，`Cache-Control: public, max-age=31536000, immutable`。
- 列表：`GET /api/gallery?limit&offset`（分页，按时间倒序）。
- 删除：`DELETE /api/gallery/{id}` → R2 删两对象 + D1 删行（软删除/墓碑可后续增强，见待定项）。
- 清空：`POST /api/gallery/clear`（需 `{confirm:true}`）→ 遍历 R2 删除 + D1 清表。

### 5.3 计量与日志

- `request_logs`：成功写全字段（含 `cost_gems`、`duration_ms`、`bytes_in/out`），失败写子集。
- `request_attempts`：失败转移时逐次落痕，便于排障。
- `daily_usage`：网关每日 request/gem 计数；`usage_counters`：面板 key 额度计数。

### 5.4 原子预占与并发租约（D1 无事务）

D1 单条 SQL 原子；写入串行化。用条件写实现在无事务下的额度与并发控制，`changes = 0` 即视为超限。

**每日额度预占**（请求数 / Gems 双条件）：

```sql
INSERT INTO daily_usage(gateway_key_id, usage_date, request_count, gem_count, updated_at)
VALUES (?, ?, 1, 0, ?)
ON CONFLICT(gateway_key_id, usage_date)
DO UPDATE SET request_count = request_count + 1, updated_at = excluded.updated_at
WHERE (? <= 0 OR request_count < ?)   -- daily_requests
  AND (? <= 0 OR gem_count < ?);      -- daily_gems
-- changes = 0 → 再读一次判定是请求数还是 Gems 超限并返回 429
```

**并发租约领取**（计数子查询 + 条件插入）：

```sql
INSERT INTO concurrency_leases(lease_id, gateway_key_id, account_id, expires_at, created_at)
SELECT ?, ?, ?, ?, ?
WHERE (SELECT COUNT(*) FROM concurrency_leases
       WHERE gateway_key_id = ? AND expires_at > ?) < ?;   -- max_concurrency
-- changes = 0 → 429；成功后在 finally 中 DELETE 释放
```

**轮询游标**（账号池 round-robin 起点，原子自增）：

```sql
INSERT INTO runtime_kv(k, v) VALUES('rr_cursor', '1')
ON CONFLICT(k) DO UPDATE SET v = CAST(CAST(v AS INTEGER) + 1 AS TEXT)
RETURNING v;
```

要点：
- `request_count` 为**预占即消耗**，失败请求不回滚（与蓝本一致）；`gem_count` 仅成功且解析出 `cost_gems > 0` 时递增。
- 租约带 `expires_at`，过期即不计入 `COUNT(*)` 过滤，无需清理任务。
- 日界暂用 **UTC**（`new Date().toISOString().slice(0,10)`），是否改配置时区见待定项。

## 6. 接口草案

### 6.1 内部面板 API（`/api/*`，Cookie 会话）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 密码门禁（已实现） |
| POST | `/api/auth/logout` | 登出（已实现） |
| GET | `/api/auth/me` | 当前身份（已实现） |
| POST | `/api/generate` | 工作台生图（走统一管线） |
| GET | `/api/gallery` | 本地作品列表 |
| GET/DELETE | `/api/gallery/{id}`、`POST /api/gallery/clear` | 画廊删除/清空 |
| GET | `/api/gallery/i/{id}` | 取图（`?t=img\|thumb`，长缓存） |
| CRUD | `/api/upstreams` | 上游管理（owner） |
| CRUD | `/api/accounts` | 账号池管理（owner）；凭据不回传 |
| CRUD | `/api/keys` | API Key 签发与管理（owner） |
| CRUD | `/api/rewrite-rules` | 改写规则管理（owner） |

> 写操作（POST/PATCH/PUT/DELETE）除会话校验外，叠加 **Origin 校验** 防 CSRF（`Origin` 缺失时放行，兼容 curl）。

### 6.2 对外网关 API（`/v1/*`、`/generate`，Bearer key 哈希校验）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/v1/nai/generate-image` | `Bearer <key>` | NAI 原生兼容，支持完整 policy |
| POST | `/v1/images/generations` | `Bearer <key>` | OpenAI 图像兼容（body 归一化为 NAI） |
| GET | `/generate` | `Bearer <key>` 或 `?token=<key>`（下游兼容） | 返回 PNG；供魔改版直链 |
| GET | `/v1/models` | `Bearer <key>` | 归一化模型列表 |

> **与下游魔改版的兼容点**：魔改版将 token 放 query（`/generate?tag=...&token=...`），因此 `GET /generate` 允许 `?token=`；无论载体如何，一律按 `api_keys.key_hash` 校验，**不存明文**。

### 6.3 鉴权矩阵

| 通道 | 载体 | 覆盖范围 | 校验方式 | 优先级/回落 |
| --- | --- | --- | --- | --- |
| 面板 API | `Cookie: <session>`（HMAC 签名 HttpOnly） | `/api/*`（除登录等公开项） | 会话签名 + 角色（owner/friend） | 主通道；面板内不认 Bearer |
| 对外网关 API | `Authorization: Bearer <key>` | `/v1/*`、`/generate` | `key_hash = SHA-256(key)` 查 `api_keys`，读 `mode`/`policy` | 主通道；`GET /generate` 可回落 `?token=` |
| 上游请求 | 账号 `credential_enc`（AES-GCM） | Worker → 上游 | 出站适配器解密并注入（如 `Authorization: Bearer`） | 仅服务端可见，绝不回传 |
| 静态资源 | 无 | SPA 资源（`ASSETS`） | 公开（是否加门禁见待定项） | 由 Workers Static Assets 直接响应 |

## 7. 实现顺序（v2）

1. 门禁联调（本地跑通登录/登出/me）。
2. D1 建表 V2（含 `accounts`/`daily_usage`/`concurrency_leases`/`request_logs`/`request_attempts`/`account_rate_state`）。
3. 上游配置 CRUD + 统一管线骨架 + 内置协议适配器（`nai-compatible` / `openai-compatible`）。
4. **账号池**：凭据加密（`CREDENTIAL_ENC_KEY`）、登录/JWT 重登、余额刷新、选号策略、冷却。
5. 工作台生图接入管线 + R2 存图 + 本地画廊（`generations`/`assets`）。
6. **对外网关**：双通道鉴权 + `mode`/`policy` + 原子预占/并发租约 + 失败转移 + 日志/留痕 + 响应头。
7. API Key 签发（哈希）与管理。
8. 改写规则（配置化）；提示词改写与内容策略。
9. 对外三端点（`/v1/nai/generate-image`、`/v1/images/generations`、`GET /generate`）+ CORS/OPTIONS。
10. 定时任务（Cron）：余额刷新、冷却回收、可选自动签到。

## 8. 安全注意

- **凭据加密不回传**：上游账号凭据 AES-GCM 加密存 D1，密钥来自独立 `CREDENTIAL_ENC_KEY`（不复用门禁 `SESSION_SECRET`）；API 只回 `has_*` 布尔，拒绝 `plain:` 明文。
- **Key 仅哈希**：对外 API Key 与面板 key 一律只存 SHA-256 哈希，不存明文；日志不得记录明文 key 与上游凭据。
- **日志脱敏**：上游错误信息截断（如 300 字）；`request_logs`/`request_attempts` 不落敏感头与 body。
- **Origin 校验**：写操作在会话之外叠加 `Origin` 校验（缺失放行以兼容 CLI），与 SameSite Cookie 互补，防 CSRF。
- **响应头白名单/剔除**：出站请求头剔除 `authorization/host/content-length/connection/transfer-encoding/accept-encoding`，强制注入上游凭据；入站响应拷贝时**剔除 `set-cookie`、`www-authenticate` 与逐跳头**，补 `Cache-Control: no-store` 与 `X-Gateway-Request-Id`。
- **改写规则只允许声明式配置**，不执行任意代码。
- **不入库不入仓**：所有密钥经 `wrangler secret put` / `.dev.vars`（已忽略）管理。本地 `docs/Reference/nai-rinko/_login-net.json` 含真实账号密码与 JWT，已被 gitignore，勿复制传播。

## 10. 待定项（待用户拍板）

- **日界时区**：`daily_usage` 用 UTC 还是配置时区。
- **静态资源是否需门禁**：SPA 资源当前公开，是否要求先登录。
- **缓存键范围**：仅逻辑参数 / 逻辑参数+上游 / 逻辑参数+上游+映射版本（影响下游 `/generate` 复用）。
- **账号选择默认策略**：`round_robin` 与 `balance_first` 的默认值及冷却阈值。
- **加密密钥是否合并**：`CREDENTIAL_ENC_KEY` 与 `ENCRYPTION_KEY` 是否统一为一个 secret。
- **画廊删除是否软删除（墓碑）**：是否需要后台回收与防重复生成。
- **自动签到**：是否纳入本版本，Cron 频率与重试策略。
