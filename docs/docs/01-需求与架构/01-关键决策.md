## 3. 关键决策

### 3.1 沿用 v1（本项目已定）

| 主题 | 决策 |
| --- | --- |
| 入站接口格式 | **同时支持 OpenAI 图像 API 与 NovelAI 原生格式**，内部归一化后路由 |
| 上游类型 | **插件化任意上游**：内置协议适配器 + 通用模板适配器，配置驱动 |
| 上游配置存储 | **D1 加密存储**（`upstreams.auth_enc` 由 `ENCRYPTION_KEY` 经 HKDF `info="upstreams"` 派生的子密钥加密），运行时增删 |
| 改写能力 | 格式与参数映射、提示词改写、内容策略与过滤、请求控制与失败转移（全要） |
| 改写规则形式 | **配置化规则（JSON 存 D1）**，不执行任意代码 |
| Key 路由 | 按 key 的**模型权限自动路由**到候选上游（优先级/权重 + 失败转移） |
| Key 额度 | **可限额、限模型、限次数、限上游**；`owner` 不限，`friend` 受限 |
| 限额后端 | **D1 计数**（原子预占，见 [03-数据模型.md](03-数据模型.md) 的 5.4） |
| 画廊来源 | **仅本地/个人作品**（R2 + D1），不对外共享、不接外部源；**按 `sid` 分区**（friend 仅自己，owner 全量/按 sid 筛选），见 [03-数据模型.md](03-数据模型.md) 的 5.2 |
| 门禁会话 | 密码哈希 + **HMAC 签名 HttpOnly Cookie**（已实现于 `apps/worker/src/lib/session.ts`）；**会话带 `sid`**（owner=`owner`，friend=分享密码 id） |
| 项目形态 | **pnpm monorepo**（`apps/web` + `apps/worker`）；Worker 用 **Hono**，D1 + R2，Workers Static Assets 单 Worker |

### 3.2 v2 新增决策 / 与蓝本的取舍

| 主题 | 本项目决策 | 对蓝本的处理 |
| --- | --- | --- |
| 门禁 | **保留本项目实现**：owner/friend 双密码 + HMAC 签名 HttpOnly Cookie 会话 | **不采用**蓝本的单一 `APP_ACCESS_KEY` + `X-Access-Key` 全局门禁 |
| 分享密码存储 | **实体化入 D1 `share_passwords`**：`salt+sha256` 哈希、`quota_bytes`、`enabled`，可增删改；owner 仍用 secret `OWNER_PASSWORD`；**旧 `FRIEND_PASSWORD` 忽略** | 蓝本无分享密码表，本版新增 |
| 画廊隔离 | **按 `sid` 分区**：`assets.owner_sid`/`generations.owner_sid`；friend 仅见自己 sid，owner 全部并可筛选；`GET /api/gallery/overview` 汇总各 sid 用量 | 蓝本画廊不分租户 |
| 字节配额 | **每分享密码 `quota_bytes`（默认 500MB）**，按 `assets.size_bytes` 求和；friend 超限拒绝且不调上游，owner 不限 | 本版新增 |
| 账号限额 | **默认每账号 10 分钟 20 张**（`capabilities_json.account_limit`）；**仅成功计入、工作台与网关全局统一计数**（`account_usage`） | 蓝本无账号级图片限额 |
| 重试/失败转移 | 单账号失败换号、最多轮遍同上游全部账号；**401 只重登不重建 token**；全池冷却兜底选最早到期账号 | 蓝本 401 处理较弱 |
| 工作台独立选号 | 工作台用 `selectionScope='workspace'` 独立游标，与网关 `gateway` 游标互不干扰；`generate` 可指定上游/模式/账号 | 本版新增 |
| 对外密钥存储 | **仅存哈希（SHA-256）**，不存明文 | **不采用**蓝本 `api_tokens.key` / `gateway_keys.key` 明文入库 |
| 账号凭据加密 | AES-GCM 存 D1，密钥为**由 `ENCRYPTION_KEY` 经 HKDF（`info="credentials"`）派生的凭据加密子密钥**（**不复用**门禁 `SESSION_SECRET`） | 蓝本用 `SHA-256(APP_ACCESS_KEY + ":ynai-accounts")` 派生，过脆，**改造** |
| 数据模型 | **通用化**：沿用本项目 `generations` / `assets` | **不照抄**蓝本强绑 NAI 的 `gallery` 画廊列 |
| 上游优先级 | **优先 `nai.rinko.ai`（多账号池），兼容其它上游** | 蓝本写死 NAI；本项目把账号池视为 `nai-compatible` 上游的一种资源 |
| 默认上游协议 | **`nai-compatible`**（默认上游即 `nai.rinko.ai` 多账号池） | — |
| 对外生图端点 | 同时提供 **`/v1/nai/generate-image`（NAI 兼容）**、**`/v1/images/generations`（OpenAI 兼容）**、**`GET /generate`（供下游魔改版调用）** | 保留蓝本三端点形态，统一由 Hono 处理，修正其路由缺口 |
| 门禁与网关密钥关系 | 两条鉴权通道**并存**：面板 API 用会话 Cookie；对外 API 用 `Bearer <key>`（哈希存储） | 蓝本只有请求头密钥，本项目在 Hono 中清晰分层 |
| 网关策略表达 | 策略字段集落在 `api_keys.policy_json`，作为改写规则的一种作用域 | 蓝本独立 `gateway_keys.policy_json`；本项目**合并进 `api_keys`**（Key 已含权限与限额） |
| 静态资源门禁 | **需要门禁**：`run_worker_first` 仅覆盖 API/网关/SPA 导航路径，静态子资源由 Assets 直出；未登录导航 `staticGate` 302 `/login`，见 [04-接口与鉴权.md](04-接口与鉴权.md) 的 6.3 | 蓝本 SPA 公开，本项目收紧 |
| 配方与画师串 | **D1 表 `presets`（`kind=recipe\|artist`）按 sid 分区**；内置 6 套画师串；画师串前端拼接到正向提示词最前；中文转 Tag 未实现 | 蓝本有 `ARTIST_PRESETS` 但非持久化，本版实体化 |
| 生成日志与资料 | **`/api/logs`（owner，workbench/gateway 分类）**；**`/api/profile`（owner，身份/站点只读 + 昵称/头像色/偏好可编辑）**，表 `app_profile` | 本版新增 |
| 前端查询缓存 | React Query `staleTime`（画廊/预设 30s、配置类 5min）、`retry:0`；图片 `Cache-Control: immutable` | 蓝本无统一缓存策略 |
| 日界时区 | **Asia/Shanghai（北京/上海时间）**，见 [03-数据模型.md](03-数据模型.md) 的 5.4 | 蓝本按 IANA 时区可配，本项目固定 |
| 画廊删除 | **不做软删除/墓碑**，直接删 R2 两对象 + D1 行，见 [03-数据模型.md](03-数据模型.md) 的 5.2 | 去重与防重生交由下游（魔改版）负责 |
| 生图结果缓存 | **不做服务端结果缓存**：网关响应一律 `Cache-Control: no-store`，每次生图回源上游，正常消耗 Gems；R2 仅存画廊对象（读图长缓存），见 [02-目标架构.md](02-目标架构.md) 的 4.1、[03-数据模型.md](03-数据模型.md) 的 5.2 | 蓝本同样 `no-store`、不缓存生图结果；去重/防重生与结果缓存属**下游（魔改版）**职责 |
| 账号选择默认策略 | 默认 **`round_robin`（轮询）**；冷却是否启用、失败次数阈值与冷却时长**由所有者运行时配置**，不写死默认值 | 见 [02-目标架构.md](02-目标架构.md) 的 4.2 |
