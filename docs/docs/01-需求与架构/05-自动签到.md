# 5 · 自动签到

> 版本：**v1.1.0** ｜ 更新日期：**2026-10-02**
> 学习参考：`docs/Reference/YesNAI_Studio_RP`（`worker/index.ts`、`README.md`、`USAGE.md`、`migrations/0001`~`0007`）。本文只吸收其**机制与工程实践**，并按本项目决策改造，不复用其表结构、鉴权与密钥模型。

自动签到纳入本版本。目标：为账号池中的每个启用账号在到点时间自动调用上游签到接口领取每日 Gems，并在失败时按可控策略重试，绝不绕过人机验证。

## 5.1 签到机制

- **触发**：Cron `*/5 * * * *`（每 5 分钟醒一次），由 Worker `scheduled` 入口调用调度逻辑。
- **多时间槽 × IANA 时区**：默认时区 **`Asia/Shanghai`**；工作日（周一~周五）与周末分别配置时间槽，如工作日 `["09:05"]`、周末 `["10:00"]`，可配置多槽。时间格式 `HH:MM`，非法值剔除，至少保留一个槽。时区用 `Intl.DateTimeFormat` 校验合法性。
- **升序补签**：对当天所有**已到点**的槽按时间**升序**排列；优先选择「当天最早且尚未尝试过」的槽（覆盖 Cron 停机跨槽的情况）；若全部已尝试，则落到最新槽进入重试。
- **失败 30 分钟退避**：可重试失败后，下一次尝试需距上次 ≥ `30 分钟`（`RETRY_BACKOFF_MS = 30 * 60 * 1000`）。
- **每槽最多 1 + 4 次**：每个槽首次尝试 1 次，失败允许最多 4 次重试（`RETRY_MAX = 4`）；换槽时重试计数归零。重试计数达上限后不再重试，等待下一槽。
- **401 自动重登**：签到返回 401（`jwt_expired`）时，用托管密码/凭据自动重登一次并回写凭据，再重试签到一次；仍失败则标记 `jwt_expired`。
- **Turnstile 终态 `manual_required`**：上游提示人机验证（响应含 `turnstile`）时，标记 `manual_required`，提示人工处理，**绝不绕过**，且不再对该账号做无意义自动重试。
- **状态机**：`pending`（等待）→ `success`（已签）/ `retry`（重试中）/ `jwt_expired`（JWT 过期）/ `manual_required`（需人工）。终态错误（`jwt_expired`、`manual_required`）不再自动重试。
- **错峰**：账号顺序随机打散，账号之间加 `3~8 秒`随机间隔，避免整批瞬时连发。
- **多 Cron 并发保护**：以时刻表上的 `lease_until`（约 10 分钟）做抢占式租约，同一时刻仅一个 Cron 执行。

> **本版本固定全局时刻表**：时区固定 `Asia/Shanghai`，工作日/周末时间槽为全局配置，**不提供每账号自定义**（蓝本的 `accounts.weekday_times/weekend_times` 扩展位本版本不启用）。签到配置/日志表见 5.4。

**本版本取值（对齐参考项目 YesNAI_Studio_RP）**：Cron `*/5 * * * *`；默认时区 `Asia/Shanghai`；默认工作日 `["09:05"]`、周末 `["10:00"]`；退避 30 分钟；每槽最多 1+4 次；租约 10 分钟；**补签启用**。

## 5.2 余额获取

- **接口**：调用上游余额接口（NAI 站点为 `GET /api/ynai/user/balance`，用账号 JWT 鉴权）。
- **写回**：解析响应中的 `balance_gems`，写回 `accounts.gems_last`。
- **刷新时点**：`/api/accounts/refresh_gems` 批量刷新（面板触发）、单账号按需刷新，以及 Cron 定时刷新（与签到同一调度）。
- **汇总**：账号列表返回 `total_gems`（各启用账号 `gems_last` 之和）供前端展示。
- 余额字段被账号选择策略 `balance_first` 使用（见 [02-目标架构.md](02-目标架构.md) 的 4.2；默认策略为 `round_robin`）。

## 5.3 凭据 / 密钥的生成与使用

- **账号凭据**：账号的 JWT / 密码 / 上游 API Token 等凭据，统一用**由 `ENCRYPTION_KEY` 经 HKDF（`info="credentials"`）派生的凭据加密子密钥**经 **AES-GCM** 加密后入库（密文形如 `enc:v1:<b64(iv)>:<b64(ct)>`，随机 12 字节 IV），不复用门禁 `SESSION_SECRET`；**任何 API 响应都不回传明文**，只回 `has_*` 布尔；拒绝 `plain:` 前缀。JWT 过期自动重登后回写新密文。
- **对外分发 key 的生成**：签发出随机 key，带可兼容下游的前缀（如 `yst-`），明文仅在**创建响应中返回一次**，随后**仅存 SHA-256 哈希**（`api_keys.key_hash`），不存明文。
- **对外分发 key 的使用**：校验时对入站 key 计算 `SHA-256` 与 `key_hash` 比对；命中后读取该 key 的 `mode`/`policy_json`（配额、限流、模型白名单、并发等），执行配额预占与策略校验。`GET /generate` 兼容 `?token=` 载体，但同样只走哈希校验。

## 5.4 数据表（本项目 D1 新建）

在**本项目 D1** 中新建签到相关表（不照搬蓝本表名/列，以下为字段草案，实现时以迁移为准）：

**`checkin_settings`（签到时刻表 / 总开关）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 单行配置（如恒为 1） |
| `enabled` | INTEGER | 总开关 0/1 |
| `timezone` | TEXT | IANA 时区，默认 `Asia/Shanghai` |
| `weekday_times` | TEXT | 工作日时间槽 JSON 数组，如 `["09:05"]` |
| `weekend_times` | TEXT | 周末时间槽 JSON 数组，如 `["10:00"]` |
| `lease_until` | TEXT | 抢占式租约到期时间，防多 Cron 并发 |
| `next_run_at` | TEXT | 下次计划时间（可选） |
| `last_attempt_slot` / `last_success_slot` | TEXT | 最近尝试/成功槽（可选，用于状态展示） |
| `status` / `last_message` / `retry_count` | TEXT/INTEGER | 调度级状态（可选） |
| `updated_at` | TEXT | 更新时间 |

> 本版本**不设** `weekday_times/weekend_times` 的每账号覆盖列，时刻表只有全局一份。

**`checkin_logs`（每次签到尝试日志）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `account_id` | INTEGER | 账号 |
| `attempted_at` | TEXT | 尝试时间（ISO） |
| `slot` | TEXT | 槽键（如 `2026-10-01T09:05`） |
| `ok` | INTEGER | 是否成功 0/1 |
| `status_code` | INTEGER | 上游 HTTP 状态码 |
| `message` | TEXT | 截断后的消息 |

> 索引建议：`checkin_logs(attempted_at DESC)`。账号级签到状态（`last_attempt_slot`、`last_success_slot`、`retry_count`、`status`）可落在 `accounts` 表的扩展列或独立状态表，实现时确定。

**调度要点（结论）**：Cron `*/5 * * * *`；默认时区 `Asia/Shanghai`；每槽最多 1+4 次；失败退避 30 分钟；账号间隔 3~8 秒；租约约 10 分钟；终态 `jwt_expired` / `manual_required` 停止自动重试。

## 5.5 与蓝本的差异

本项目对参考项目做如下改造：
- **门禁**：使用本项目 owner/friend **双密码 + HMAC 签名 HttpOnly Cookie 会话**，不采用蓝本单一 `APP_ACCESS_KEY` + `X-Access-Key`。
- **密钥**：对外分发 key **仅存 SHA-256 哈希**，不采用蓝本 `api_tokens.key` / `gateway_keys.key` 明文入库。
- **凭据加密密钥**：使用由单一 `ENCRYPTION_KEY` 经 HKDF（`info="credentials"`）派生的子密钥（不复用门禁 `SESSION_SECRET`），不采用蓝本从 `APP_ACCESS_KEY` 派生。
- **上游**：默认 `nai-compatible`（`nai.rinko.ai` 多账号池），兼容 `openai-compatible` 与模板适配器。
- **数据模型**：签到配置/日志表建在本项目 D1，字段命名与通用表一致；不照抄蓝本 `autocheckin_*` 表结构。

## 5.6 前端能力与接口确认（v1.1.0）

签到设置页（`apps/web/src/routes/CheckinSettings.tsx`）已实现：

- **账号池按上游分组**：拉取 `GET /api/upstreams` 与 `GET /api/accounts`，按 `account.upstream_id` 分组展示，每组显示账号数；每个账号显示状态、`gems_last`、`has_api_token`（缺 Token 高亮）。
- **单账号签到**：账号行内「单独签到」按钮 → `POST /api/accounts/{id}/test` → 调 `performCheckin(..., {manual:true})`，返回 `CheckinResult`（`ok/status/slot/status_code/message`），前端即时回显结果并刷新账号列表。
- **全量测试**：右上角「立即测试全部账号」→ `POST /api/checkin/test`，顺序遍历启用账号并返回 `{total, success, items}`。
- **设置与运行状态**：`GET/PATCH /api/checkin/settings` 读写总开关、时区、工作日/周末时间槽；展示 `status`、`next_run_at`、`lease_until`、`last_message`。

> 接口已确认（实际路由见 `apps/worker/src/routes/accounts.ts`、`routes/checkin.ts`）：
> `POST /api/accounts/:id/test`（单账号）、`POST /api/checkin/test`（全账号）、`GET|PATCH /api/checkin/settings`。
> 单账号签到复用与定时任务相同的 `performCheckin`，保证状态机与日志一致。
