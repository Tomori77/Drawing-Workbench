## 4. 目标架构

### 4.1 统一管线（工作台与外部 API 共用）

```
入站适配 → 归一化 CanonicalRequest → 改写管线 → 路由选上游/选账号 → 出站适配 → 透传 → 响应归一化
```

- **入站适配**：`/v1/images/generations`（OpenAI）、`/v1/nai/generate-image` 与 `/ai/generate-image`（NAI）、`GET /generate`（下游简式 query）→ CanonicalRequest。
- **CanonicalRequest**：`model`（逻辑名）/ `action`（txt2img·img2img·inpaint）/ `prompt{positive,negative}` / `params` / `references[]` / `n`。
- **改写管线**：参数映射 → 提示词改写 → 内容策略 → 请求控制（头/鉴权/超时/重试）。
- **路由**：按 key 的模型权限筛选候选上游，按优先级/权重选择；命中 `nai-compatible` 上游时进入**账号池选号**（见 4.2）。当前实现仅取 priority 首个启用上游（多上游权重路由见 [09-待定与讨论.md](09-待定与讨论.md)）；工作台可通过 `upstream_id` 显式指定上游。
- **选号游标隔离**：调用方以 `selectionScope`（`workspace` / `gateway`）区分轮询游标键（`rr_cursor:workspace:<upstream>` / `rr_cursor:gateway:<upstream>`），工作台与网关互不干扰（见 4.4）。
- **出站适配**：内置协议适配器（`nai-compatible` / `openai-compatible`）+ 通用模板适配器（URL/方法/头/body 模板 + 响应字段映射）。
- **响应归一化**：按入站格式还原（OpenAI→b64/url；NAI→zip/base64；`/generate`→图片二进制）。
- **不做服务端结果缓存**：**每次生成都回源上游**，正常消耗 Gems；网关响应一律 `Cache-Control: no-store`。R2 仅存持久画廊对象（`img/`、`thumb/`），不含生图结果缓存。去重/防重生与结果缓存是**下游（魔改版）**的职责，本项目不维护上述机制。

### 4.2 账号池（Account Pool）

账号池是 **`nai-compatible` 上游的一种资源**（非独立上游类型）；`openai-compatible` 与模板适配器可使用单账号凭据，也可扩展为池。

- **实体**：`accounts`（见 [03-数据模型.md](03-数据模型.md) 的 5.1），归属某个 `upstream_id`，默认归属 `nai.rinko.ai` 上游。
- **凭据存储**：`credential_enc` 为 AES-GCM 密文（`enc:v1:<b64(iv)>:<b64(ct)>`，随机 12 字节 IV），密钥为 `ENCRYPTION_KEY` 经 HKDF（`info="credentials"`）派生的凭据加密子密钥；**凭据永不出现在 API 响应**，公开视图仅回 `has_jwt / has_password / has_api_token` 布尔。拒绝 `plain:` 前缀明文。
- **Token 获取**：创建账号时自动登录并 `provisionToken` 创建上游 API Token（命名 `DW-YYMMDDHHmm`，`shanghaiTimestamp` 生成，冲突时追加毫秒后缀）；支持 `POST /api/accounts/provision_all` 批量获取（单批上限 50）、`POST /api/accounts/batch` 批量新增（单批上限 30）、`POST /api/accounts/batch_delete` 批量删除。
- **JWT 过期自动重登（401 行为）**：生图或签到返回 401 时，**仅用托管密码重登（`refreshJwt`）回写 `credential_enc`，不重建 API Token**；重登成功后用原 token 对同一账号重试一次，**重登成功不计入失败**；确认放弃（重登失败或重登后仍失败）才累加一次失败并考虑换号。
- **账号图片限额**：默认每账号 **10 分钟 20 张**（`DEFAULT_ACCOUNT_LIMIT`，窗口 600000ms / 20 张），可由上游 `capabilities_json.account_limit = {window_ms, max_images}` 覆盖；**仅成功计入**（`result.ok` 且按返回图片数累加）；**工作台与网关共享同一计数**（表 `account_usage`，`addAccountImages`）；达限账号在选号时跳过，全部达限时进入兜底（见下）。
- **余额刷新**：定时或按需调用上游余额接口，成功后写回 `gems_last`（详见 [05-自动签到.md](05-自动签到.md) 的余额获取一节）。
- **账号选择策略**：由**所有者在运行时配置**（按 `upstream_id` / 全局配置持久化）。默认策略为 **`round_robin`（轮询）**。候选策略至少：
  - `round_robin`（轮询游标，**默认**）：以 `runtime_kv` 中的持久游标原子自增为起点，在启用账号间轮转分摊（游标写法见 [03-数据模型.md](03-数据模型.md) 的 5.4）；
  - `balance_first`（余额优先）：候选序列按余额降序，优先使用余额最高的账号；
  - `fixed`（固定账号）：固定使用配置指定的账号，适合单账号或指定用途。

  策略需保留**扩展位**（如 `least_used` 按最近使用时间最少优先）。返回序列首个为本次选号，其余为失败转移顺序。工作台还可显式传 `account_id`（`fixed` 模式），选号时将其提到候选首位、其余按策略顺序紧随（用于失败转移）。
- **失败转移与全池兜底**：单个账号失败（含超时/连接错误）即换下一个候选，**最多轮遍同上游全部账号**；候选耗尽返回 `ALL_ACCOUNTS_FAILED`（502）。当**全部可用账号都在冷却**时，以「冷却最早到期」兜底继续尝试（`degraded="cooldown"`）；当**全部账号都达图片限额**时，以「剩余额度最多、其次冷却最早到期」兜底继续尝试（`degraded="limit"`）；账号池完全无可用账号（无 token）才返回 `NO_ACCOUNT`。
- **账号级冷却**：失败（401/402/429/5xx）时累加 `failure_count` 并写 `cooldown_until`；冷却期内跳过该账号（`account_rate_state`，见 [03-数据模型.md](03-数据模型.md) 的 5.1）。**是否启用冷却、连续失败次数阈值、冷却时长，均由所有者在面板运行时配置**（默认启用、阈值 3、时长 5 分钟，存上游 `capabilities_json.account_cooldown` 或 `runtime_kv`）；Cron 每 5 分钟回收到期冷却（见 [08-密钥与绑定.md](08-密钥与绑定.md) 与 09 待定项更新）。

### 4.3 对外网关

- **`mode`**：`passthrough`（字节原样透传，不解析不改写）｜ `restricted`（解析、校验策略、按 `parameter_mode` 改写）。
- **`policy` 字段全集**（存 `api_keys.policy_json`，restricted 生效）：

  | 字段 | 含义 |
  | --- | --- |
  | `allowed_models` | 允许模型白名单（空=不限制；不在白名单→403） |
  | `daily_requests` | 每 key 每日请求上限（原子预占，超限 429） |
  | `daily_gems` | 每 key 每日 Gems 上限（原子预占，超限 429） |
  | `max_concurrency` | 每 key 同时在途上限（并发租约，超限 429） |
  | `parameter_mode` | `fixed` 时启用固定参数合并 |
  | `fixed_parameters` | 强制覆盖的参数对象（合并进 `parameters`） |
  | `limits` | 各参数上下界 `{field:{min,max}}` |
  | `allow_img2img` | 是否允许图生图 |
  | `allow_inpaint` | 是否允许重绘/局部重绘 |
  | `allow_extra_parameters` | `false` 时拒绝未知参数（按已知参数白名单） |

  > 蓝本还读取但未列入白名单的 `models`、`max_n`/`max_n_samples`、`max_width/height/steps/scale` 等，本项目统一通过 `limits` 表达，字段集以前端为准，避免前后端不一致。
- **restricted 参数改写**：`fixed` → 深拷贝 body 后把 `fixed_parameters` 浅合并进 `parameters`；其余 → 保留原始字节（但已完成策略校验）。
- **失败转移分级**：`401 / 402 / 429 / 5xx` → 换下一个候选账号；其余 `4xx`（参数错误）→ **立即透传**，不转移。全部失败 → 502。
- **请求尝试留痕**：每次尝试写 `request_attempts(request_id, account_id, attempt_no, status_code, error)`。
- **响应头**：回传 `X-Account-Id`（实际服务账号）、`X-Gateway-Attempts`（总尝试数）、`X-Gateway-Request-Id`。
  > 蓝本存在 `X-Ynai-Account` / `X-YesNAI-Account` 命名不一致与大小写问题，本项目统一为 `X-Account-Id` / `X-Gateway-Attempts`。

### 4.4 配方与画师串（Presets）

配方（参数快照）与画师串（提示词片段）以 **D1 表 `presets`** 持久化，**按会话 `sid` 分区**（与画廊 `owner_sid` 同语义）。

- **种类 `kind`**：`recipe`（存 `payload_json`，为 `GenerateParams` 快照）｜ `artist`（存 `content`，画师串原文）。
- **权限**：friend 只能管理自己 sid 的预设；owner 只能管理 owner sid，**可只读查看他人**（`GET /api/presets?sid=` 传 sid、`GET /api/presets/overview` 汇总各 sid 数量）。修改/删除仅限本人 sid（owner 亦不能改他人）。
- **内置画师串**：`ensureBuiltinArtists` 在某 sid 下 `artist` 记录为 0 时种入 **6 套内置画师串**（`builtin=1`，原样照搬参考项目，见 `apps/worker/src/presets/builtinArtists.ts`），不覆盖用户编辑/删除结果。
- **使用方式**：画师串由**前端**在提交时拼接到正向提示词最前（`${artistContent}, ${prompt}`），不改动输入框内容；复现时从参数 `artist` 还原并剥离提示词前缀。
- **未实现**：中文转 NAI Tag（仅占位），见 [09-待定与讨论.md](09-待定与讨论.md)。

### 4.5 统一管线补充（工作台与网关共用）

- 入站归一化统一走 `inboundToCanonical`（工作台）与 `openaiInboundToCanonical` / `queryInboundToCanonical`（网关），均产出 `CanonicalRequest`。
- 选号、限额、重试、冷却、留痕均在 `runPipeline` 内统一处理，工作台与网关仅在「作用域/游标」「是否做网关配额预占与策略改写」上不同。
- 工作台经 `POST /api/generate` 调用；网关经 `/v1/*`、`/generate` 调用（Bearer key 鉴权）。两者共享账号池与 `account_usage` 计数。
