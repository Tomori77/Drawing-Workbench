图片对象存 **R2**，元数据与计数存 **D1**。V2 合并本项目 v1 通用表与蓝本账号池/网关表，**字段以本项目通用化为准**。迁移文件唯一来源为 `apps/worker/migrations/0001~0007`。

## 5. 数据模型（D1 · V2）

### 5.1 表清单

| 表 | 来源 | 关键字段 | 用途 |
| --- | --- | --- | --- |
| `upstreams` | 本项目 v1 | `id, name, type, base_url, auth_enc, models_json, capabilities_json, transform_json, priority, weight, enabled, created_at` | 上游配置（`type` 含 `nai-compatible` / `openai-compatible` / 模板） |
| `accounts` | **吸收蓝本**（通用化） | `id, upstream_id, label, username, credential_enc, gems_last, enabled, status, failure_count, cooldown_until, last_success_at, created_at, updated_at` | 账号池；`credential_enc` AES-GCM 加密，永不回传 |
| `models` | 本项目 v1 | `logical_name, upstream_id, upstream_model, enabled` | 逻辑模型到上游模型映射 |
| `api_keys` | 本项目 v1 **合并**蓝本 `gateway_keys` | `id, key_hash, name, role, mode, policy_json, allowed_models_json, allowed_upstreams_json, quota, used_count, rate_limit, expires_at, enabled, created_at` | 分发 key；**仅存 `key_hash`**；`mode`/`policy_json` 承自蓝本 |
| `daily_usage` | **吸收蓝本** | `gateway_key_id, usage_date, request_count, gem_count`，唯一键 `(gateway_key_id, usage_date)` | 每 key 每日用量（日界 **Asia/Shanghai**，见 5.4） |
| `concurrency_leases` | **吸收蓝本** | `lease_id, gateway_key_id, account_id, expires_at, created_at` | 并发租约（带过期，无清理任务） |
| `request_logs` | **吸收蓝本** | `request_id, gateway_key_id, account_id, path, mode, status_code, ok, duration_ms, bytes_in, bytes_out, cost_gems, created_at` | 请求级记账 |
| `request_attempts` | **吸收蓝本** | `request_id, account_id, attempt_no, status_code, error` | 每次尝试明细 |
| `account_rate_state` | **吸收蓝本（本项目启用）** | `account_id, failure_count, cooldown_until, last_status` | 账号级冷却；蓝本为死表，本项目启用 |
| `rewrite_rules` | 本项目 v1 | `id, scope, match_json, action_json, priority, enabled` | 声明式改写规则（网关 policy 视作一种 scope） |
| `usage_counters` | 本项目 v1 | `key_id, period, count, updated_at` | 通用计数（面板 key 额度）；与 `daily_usage` 分工：前者面板、后者网关 |
| `runtime_kv` | **吸收蓝本** | `k, v` | 运行时键值：账号池 `round_robin` 游标（工作台/网关分键）、签到状态、工作台设置、冷却配置等（5.4） |
| `generations` | 本项目 v1（通用化） | `id, key_id, role, upstream_id, account_id, params_json, status, cost_gems, created_at, owner_sid` | 生图任务元数据（不绑 NAI 专列）；`owner_sid` 为新增列（0006），用于画廊隔离 |
| `assets` | 本项目 v1（通用化） | `id, generation_id, r2_key, thumb_r2_key, mime, width, height, created_at, owner_sid, size_bytes` | 图片资源元数据，二进制在 R2；`owner_sid`（0006 新增）用于分区，`size_bytes`（0006 新增）用于字节配额 |
| `checkin_settings` | **本项目新增**（0003，见 [05-自动签到.md](05-自动签到.md)） | `id, enabled, timezone, weekday_times, weekend_times, lease_until, next_run_at, last_attempt_slot, last_success_slot, status, last_message, retry_count, updated_at` | 签到时刻表/总开关（单行 `id=1`） |
| `checkin_logs` | **本项目新增**（0003，见 [05-自动签到.md](05-自动签到.md)） | `id, account_id, attempted_at, slot, ok, status_code, message` | 每次签到尝试日志 |
| `share_passwords` | **本项目新增**（0006） | `id, label, salt, password_hash, role, quota_bytes, enabled, created_at, updated_at` | 朋友分享密码；`salt+sha256` 哈希，`quota_bytes` 默认 500MB；owner 仍用 secret，不落库 |
| `presets` | **本项目新增**（0007） | `id, owner_sid, kind, name, content, payload_json, builtin, created_at, updated_at` | 配方（`recipe`）/画师串（`artist`），按 `owner_sid` 分区；内置画师串 `builtin=1` |
| `account_usage` | **本项目新增**（0005） | `account_id, window_start, image_count, updated_at` | 账号图片限额全局计数（窗口内成功张数，工作台与网关共享） |
| `app_profile` | **本项目新增**（0004） | `id, nickname, avatar_color, preferences_json, updated_at` | 单例个人资料（`id=1`） |

> **不采用**蓝本 `gallery` 表（强绑 NAI 的 `artist/model/seed/sampler/...` 列）；这些参数统一进 `generations.params_json`，画廊查询走通用字段。
> **不建**蓝本 `gateway_keys_v7` 中间表与 `active_concurrency` 死列。
> 迁移顺序：`0001_init`（通用表 + `generations`/`assets`）→ `0002_gateway`（计量/租约/`runtime_kv`）→ `0003_checkin` → `0004_profile` → `0005_account_usage` → `0006_share_passwords`（并对 `assets` 增 `owner_sid,size_bytes`、`generations` 增 `owner_sid`）→ `0007_presets`。

### 5.2 持久画廊

> **本项目不做生图结果缓存**：R2 仅存持久画廊对象（`img/`、`thumb/`），不含任何生成结果缓存。每次生图回源上游，正常消耗 Gems；网关响应一律 `Cache-Control: no-store`。去重/防重生与结果缓存是**下游（魔改版）**的职责。

- **分区与隔离**：`assets.owner_sid` 与 `generations.owner_sid` 标识归属（owner=`owner`，friend=分享密码 id）；friend 仅能读写自己 sid，owner 默认全部并可按 `?sid=` 筛选。
- 上传：原图 → R2 `img/{uuid}`，缩略图 → R2 `thumb/{uuid}`（缩略图由前端 canvas 生成后一并上传）；D1 写 `generations` + `assets` 元数据（含 `owner_sid`、`size_bytes`）。缩略图上传走 `POST /api/gallery/{id}/thumb` 并累加 `size_bytes`。
- 取图：`GET /api/gallery/i/{id}?t=img|thumb` → 校验 `owner_sid` 访问权限后读 R2，`Cache-Control: public, max-age=31536000, immutable`。
- 列表：`GET /api/gallery?limit&offset&sid`（分页，按时间倒序；owner 可传 `sid` 过滤）。
- 信息：`GET /api/gallery/{id}/meta` → 合并 `assets` 与关联 `generations`，返回模型/动作/提示词/参数及尺寸等（兼容旧扁平格式，负向提示词取 `negative_prompt`）。
- 总览：`GET /api/gallery/overview`（owner）→ owner 一行 + 每个分享密码一行，含 `used_bytes`/`count`（按 `owner_sid` 聚合 `size_bytes`）。
- 删除：`DELETE /api/gallery/{id}` → 校验权限后 R2 删两对象 + D1 删行（若 `generation` 无剩余 `asset` 则一并删）。**不做墓碑/软删除**。
- 清空：`POST /api/gallery/clear`（需 `{confirm:true}`，owner 可带 `sid` 定向清空；friend 只能清自己）。

### 5.2.1 字节配额（分享密码）

- `share_passwords.quota_bytes` 默认 500MB（`524288000`，可由 env `DEFAULT_SHARE_QUOTA_BYTES` 覆盖）。
- 用量按 `SELECT SUM(size_bytes) FROM assets WHERE owner_sid=?` 统计（原图 + 缩略图）。
- `POST /api/generate` 在 friend 会话下检查：`used >= quota` → 403 `quota_exceeded`，**不调用上游**；owner 不检查。

### 5.3 计量与日志

- `request_logs`：成功写全字段（含 `cost_gems`、`duration_ms`、`bytes_in/out`），失败写子集。
- `request_attempts`：失败转移时逐次落痕，便于排障。
- `daily_usage`：网关每日 request/gem 计数；`usage_counters`：面板 key 额度计数。

### 5.4 原子预占与并发租约（D1 无事务）

D1 单条 SQL 原子；写入串行化。用条件写实现在无事务下的额度与并发控制，`changes = 0` 即视为超限。

**每日额度预占**（请求数 / Gems 双条件）：

```sql
INSERT INTO daily_usage(gateway_key_id, usage_date, request_count, gem_count, updated_at)
VALUES (?, ?, 1, 0, ?)
ON CONFLICT(gateway_key_id, usage_date)
DO UPDATE SET request_count = request_count + 1, updated_at = excluded.updated_at
WHERE (? <= 0 OR request_count < ?)   -- daily_requests
  AND (? <= 0 OR gem_count < ?);      -- daily_gems
-- changes = 0 → 再读一次判定是请求数还是 Gems 超限并返回 429
```

**并发租约领取**（计数子查询 + 条件插入）：

```sql
INSERT INTO concurrency_leases(lease_id, gateway_key_id, account_id, expires_at, created_at)
SELECT ?, ?, ?, ?, ?
WHERE (SELECT COUNT(*) FROM concurrency_leases
       WHERE gateway_key_id = ? AND expires_at > ?) < ?;   -- max_concurrency
-- changes = 0 → 429；成功后在 finally 中 DELETE 释放
```

**轮询游标**（账号池 round-robin 起点，原子自增；键按作用域与上游分隔）：

```sql
INSERT INTO runtime_kv(k, v) VALUES(?, '1')
ON CONFLICT(k) DO UPDATE SET v = CAST(CAST(v AS INTEGER) + 1 AS TEXT)
RETURNING v;
-- 键示例：rr_cursor:workspace:<upstream_id> / rr_cursor:gateway:<upstream_id>
```

要点：
- `request_count` 为**预占即消耗**，失败请求不回滚（与蓝本一致）；`gem_count` 仅成功且解析出 `cost_gems > 0` 时递增。
- 租约带 `expires_at`，过期即不计入 `COUNT(*)` 过滤，无需清理任务。
- **账号图片限额**用 `account_usage` 的 `image_count`/`window_start` 做窗口内计数（见 [02-目标架构.md](02-目标架构.md) 的 4.2）；仅成功计入，达限跳过。
- **日界使用 `Asia/Shanghai`（北京/上海时间）**，不再用 UTC。实现提示：`apps/worker/src/lib/time.ts` 用 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Shanghai' })` 取 `YYYY-MM-DD`（`todayInShanghai`）；`shanghaiTimestamp` 生成 `YYMMDDHHmm` 用于 Token 命名。
